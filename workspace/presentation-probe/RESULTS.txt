Important observations/limits:
  - A real NSApplication run loop is required for this native diagnostic;
    merely polling a never-running AppKit application yielded blank capture.
  - addPresentedHandler is not called on this D3DMetal path; the log records
    callbacks=0 honestly. This probe requires the positive own-window image
    plus byte-exact drawable/backbuffer data, not a fabricated callback.
  - presentedTime is 0 even for the independent real native-Metal baseline
    whose blue window was positively captured. Timestamp alone is not proof
    of failure on this hardware/runtime.
  - DMN_PRESENT_FALLBACK must be unset: the host rejects it. The optional
    PRESENTATION_MANUAL_CONTROL negative diagnostic cannot turn PASS on;
    all scored pixels/screenshots precede it. It was not enabled in PASS runs.
  - The adapter still deliberately simulates the Apple7 classification gate;
    real GPU work, shader execution and pixel data are not simulated. Runs use
    the parent's public-Metal software residency shim, managed texture mode
    and renderpass normalization. This is not Apple official support or a
    complete D3D12/Metal conformance result; no game was launched by this test.
  - GFXT host ABI is third-party reconstructed open-source interoperability,
    not an Apple-documented native WSI API. The original Apple framework is
    unchanged. Only UTM's OS/window/event/registry/path/allocation/library/
    monitor/adapter/swapchain/logging service source files are linked. NOT
    linked: UTM initializer, COM hooks, private exported Apple flags, Metal
    swizzles, sparse/share patches. UTM checkout is unmodified.
  - Window capture uses the installed public legacy CoreGraphics API for
    precisely this probe's owned window. No other windows are captured and
    no screen-capture permission or global UI preference is requested.
